Arsenal Team Board

Features

Grouped from every ticket's - feature: line by tools/board-features.mjs (T-271) — the same rules node tools/board.mjs features uses, so the two can never disagree. YOU: is the single next thing that needs a person; a dash means an agent (or nobody) owns the next step.

Where the work actually is

Read from git, not from ticket status. origin/main is production; origin/staging is the staging site. Amplify builds from the remote, so a commit that has not been pushed is in no environment at all, however finished it is.

Stalled

From tools/board-sweep.mjs, which derives these from git rather than from ticket fields — branch exists, worktree exists, tree is dirty, work already merged. Those cannot be forgotten into being wrong; a status field can. The sweep proposes and never closes anything.

Everything on the shared board, collapsed by default now that Features above is the lead view. Purple is yours — human-review and staging are waiting on you and no agent can move them; tester-review is finished work waiting on a tester. Status is self-reported: agents often skip in-progress entirely, so a low count there means the field went unset, not that nothing is running. The active-branch tile above is the reliable one, and done is cross-checked against git by the sweep below.

Worktrees

One checked-out directory per branch. Uncommitted counts files that exist in that tree and nowhere else — a closed ticket whose code is still only here is not safe yet.
